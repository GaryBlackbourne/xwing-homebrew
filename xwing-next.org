* concept

Ships fly around, shooting at eachother, gaining objective points, and
killing eachother.

The game is divided into *sessions*, one session is made up of three
parts *setup*, *mission*, *cleanup*.

** Setup
- In the setup, declare the players who participate.
- Declare the exact ships, pilots, upgrades (hence *list*) the player
  controls.
- choose one mission
- declare alliances (groups of players who are friendly to eachother)
- set up the table according to the mission rules
- set up player assets (ships, ship cards, dice, etd)
  
** Mission
*** deploy forces
- place forces on to the map respecting the *deployment restrictions*
  and the mission rules
- set up ship meta assets according to the mission rules (starting
  energy, charge, wing/setup, etc.)
*** rounds
- play the amount of *rounds* the mission specifies, or until the mission
  end-criteria is met
*** mission end criteria
- each mission must contain at least one criteria which marks the end of the
  mission

** Cleanup
- calculate faction points
- calculate player points
- declare winner

* Modules

** Map
The play area is called the *map*. Every entity in the game which can
have "distance" from anything must be placed in between the map
borders.

*** Layout
The layout is the geometry of mission entities and obstacles (= "terrain") on
the map.

** Units
Every unit in the game must consist of three parts. One base being the gameplay
projection of a unit, one miniature according to the unit's type and one board
containing all meta information about the unit, like skills, HP, weaponry, and
actions.

There are three types of units: small, medium and large. Depending on the size,
each miniature has an appropriatley sized base which helps with maneuvering and
angles.

*** Model

Miniature of the unit, each ship is 1/220 scale. No restriction about painting
and looks, if both players are able to recognize the unit then it is battle ready.

*** Metadata

Each unit interacts with other game entities based on the metadata linked to
it. This metadata consists of keywords and numerical values, which determines
the units affiliation, and it's action's availability and
effectiveness. Different pars of a unit (eg ship/pilot/loadout/upgrade/talent)
contributes to differet meta values.

**** Unit Metadata

***** Faction

Faction is a ~keyword~ representing the faction which the unit belongs
to. Mission rules and card rules may refer to this keyword of a unit. Units with
the same faction keyword are ~friendly~ to eachother, unless stated otherwise by
a mission rule.

***** Affiliation

Affiliation is a logical group representing a player. It is marked by a color,
choosen by the player if mission rules don't specify it. Every unit with the
same affiliation is ~friendly~ to eachother.

***** Ship type

Ship type declares the chasses of the ship, it's default values, loadout and
upgrade slots.
Each ship type has the following numeric values associated:
- maximum hull value
- maximum shields value
- attack value
- movement points
- maneuverability points
Each ship type also lists two types of upgrade slots: ~system-upgrade~ and
~hardpoint~ slots. Additional weaponry might be attached to ~hardpoint slots~,
and system modifying upgrades can be installed to ~system-upgrade~ slots.

***** Hull

The ship's ~hull~ value represents it's physical condition. If this value
reaches 0, the unit dies. It's initial value is set by the ship's type.

***** Shields

The ship's ~shield~ value represents it's shields condition. Shields are a
defensive mechanism, lowering or neutralizing damage dealt to a unit. A unit
with shield value of 0 does not benefit from shield protection.

***** Attack value

The ship's attack value represents the firepower of it's primary
weaponry. During engagement the attack value of a ship is the number of dice
that the player may roll for a primary attack. Ships have a primary attack
value, set by their type, also different weaponrs might have different attack
values on one unit. More on this topic in [[*shooting][shooting.]]

***** Movement points

The ship's movement points are it's speed. Movement points are spend during
movement phase. For each point a unit may move one step. More on this in
[[maneuveurs]]. It's initial value is set by the ship's type.


***** Maneuverability points

The maneuverability points represent how many turns a unit may do in one maneuver
step. It's initial value is set by the ship's type.

***** Agility

The agility value represent how much can a ship turn after each step. This value
represents the amount of segments, and symmetrical to the velocity vector. It's
initial value is set by the ship's type.

***** Aim skill

This value represents the skill of the pilot in aiming. Affects how hard it is
for one blast to hit the target. It's initial value is set by the pilot.

***** Evasion skill

This value represents the skill of the pilot in evading incomming shots. While
defending, this value makes the unit harder to hit.

***** Actions list

This is a list of actions a unit may make. Actions can be given to a unit by a
ship (like targeting computer) or from the pilot (like focus), or a upgrade,
talent, or loadout.

**** Building a unit

Every metadata of a unit must be stored on a unit card or board, built by
the player from assets. Building a unit means the following:

1. Declare faction
2. Select one ship type from the factions ship list
3. Select an appropriate pilot from the factions pilot list
4. Select loadout for the ships loadout slots
5. Select talents for the pilots taalent slots
6. Select upgrades for the ships upgrade slots

** mechanics

*** maneuveurs

Maneuveuring in the game uses five manuveur tools. Each is a "rod"-like template
with different lengths, and curved endings, which match the curve of the
bases. Middle line is indicated to access more accurate placement.

For each movement point a unit may move 50 mm. This can be measured from the
front side of the base from the starting position to the back side of the base
at the end position. After one step, the unit may rotate any amount of degrees
in any direction, in the angle determined by the agility.

A unit can make any number of moves, as long as it has movement points, but it
can only turn as many as many maneuverability points it has.
