* Concept
This document describes the system for a tabletop wargame. The system is heavily
inspired by ~X-Wing TMG~. The system's main goal is to provide foundations for
flight based wargames without putting restrictions on game theme and art.

The main concempt of the engine revolves around spacecrafts or aircrafts flying
around as ~units~, while engaging with eachother and other game assets and while
doing so, gaining objective points, and killing eachother.

This document only specifies systems used in one ~session~, so potential
campaigns, linked missions, or other more abstract systems may be built on top
of it.

* Game flow
The game is divided into ~sessions~. One session means one game, where the
starting criteria of a session virtually describes every possible game flow
paths, (even if there is continuum-infinite about them), and from a sessions
start to a sessions end, no external new information will modify the game's
state space outside of true-random values.

A session is made up of three parts:
- setup
- mission
- cleanup
  
** Setup
The setup part is where all assets, rules, and information are fixed which
are needed for the full session. The steps of one session setup are:
1. Declare ~mission~
   - Declare mission assets
   - Declare mission goal
   - Declare mission end criteria
   - Declare ~alliances~ (groups of players/NPCs who are friendly to eachother)
2. Declare the players who participate
3. Declare the units for each player, and/or NPCs (respecting mission restrictions)
4. set up the table according to the mission rules

** Mission
The mission is a concept which describes the starting state, end criteria,
victory points (if any), and alliances for each game session. Playing a(n
already set up) missison means proceeding through the next three-plus-one parts
of it.

*** Deploy forces
In the deployment part, players place their units on to the map respecting the
~deployment constraints~ if they are specified in the mission.

*** Rounds
During the game the players play rounds. A game round is made up of phases:
- start of round
- planing phase
- activation phase
- engagemnet phase
- end of round

*** End of mission
The mission must specify an ~end criteria~. If that end criteria is met, the game
ends immediately.

** Cleanup
After the mission end criteria is met, the mission ends and the results are
calculated. Every mission must specify how to determine the winner. Note, that
the winner might be one or more player, an NPC, or a faction as well.

* Entity hierarchy

** Entities
Everything that is representegd in the game with a token, model, overlay, or any
other physical object is called an ~entity~.

*** Overlays
Overlays are entities with thin assets which can be applied onto eachother,
providing effects and possibilities on a region. The first overlay which is
placed in every game is called the ~map~, allowing every other entity to be
placed.

Overlays have two kinds, coering, and non-covering. Covering overlays remove
effects of overlays bellow, while non-covering overlays simply add their effect
on top of the overlays below.

Overlay effects always calculated from the bottom to the top, taking effect at
the same time.

The most common overlay is the ~map~.  Every entity in the game which can have
"distance" from anything must be placed on the map.

*** Objects
Objects are entities which can be placed on the map, effectively taking up space
and cannot overlap with eachother.

Certain edge cases might force objects to overlap, movement rules ellaborate on
how to place objects under these circumstance. By default, the newly placed
object has to be placed to the closest available space to the originally
specified space so objects in any stable game state, they do not overlap. Other
rules may override this behavior but **object overlapping is always strictly
forbidden in any stable state**.

**** Unit
Units are objects which are controlled by a player or a game mechanic
(NPC). They are the core assets of every game.

**** Obstacles
Obstacles are non controlled entities on the map, which only affects
units in the 3 following ways:
- obstruction: one unit's ~line of sight~ on another unit is ~obstructed~ if
  there is an obstacle between them
- collision: a unit must not move to overlap an obstacle, if it doesn't have a
  choice suffer penalty. Movement rules ellaborate on object placement in edge
  cases otherwise follow the default rule.
- destructible: can be targeted, locked, attacked. Have HP, and destroyed if HP
  is decreased to 0.

**** Items
Items are non controlled entities on the map, with slightly different properties
than obstacles.
- obstruction: they do not obstruct ~line of sight~
- collision: a unit must not overlap with an item, but collision doesn't always
  cause penalty over a unit.
- destructible: an item may or may not be destructible

* Game concepts 

** Meta
*** Layout
The layout is the geometry of entities in one game. Every mission starts by
specifying the map constraints (size and form) and necessary mission entities,
like:
- applying ~overlays~ for mission effects if required
- placing ~obstacles~ if required
- placing ~items~ if required
- specifying unit ~deployment~ constraints if required

*** Game flow
The game is divided into ~rounds~. Players proggress through several ~phases~
where they take ~turns~ interacting with their units, other players, other game
entities or rules.

The amount of rounds in a game is specified by the ~mission~.

**** Phases
The game differentiates between 4 phases
1. *start of round*
   This phase is only a reference for rules and triggers

2. *activation phase*
   In this phase, players take ~turns~ activating their units, make moves with
   them, and performing ~actions~.

3. *engagement phase*
   In this phase, players take ~turns~ engaging with their ~units~.

4. *end of round*
   This phase is only a reference for rules and triggers.

*** mechanics

**** maneuveurs

Maneuveuring in the game uses five manuveur tools. Each is a "rod"-like template
with different lengths, and curved endings, which match the curve of the
bases. Middle line is indicated to access more accurate placement.

For each movement point a unit may move 50 mm. This can be measured from the
front side of the base from the starting position to the back side of the base
at the end position. After one step, the unit may rotate any amount of degrees
in any direction, in the angle determined by the agility.

A unit can make any number of moves, as long as it has movement points, but it
can only turn as many as many maneuverability points it has.

** Units
Every unit in the game must consist of three parts. One base being the gameplay
projection of a unit, one miniature according to the unit's type and one board
containing all meta information about the unit, like skills, HP, weaponry, and
actions.

There are three types of units: small, medium and large. Depending on the size,
each miniature has an appropriatley sized base which helps with maneuvering and
angles.

*** Model

Miniature of the unit, each ship is 1/220 scale. No restriction about painting
and looks, if both players are able to recognize the unit then it is battle ready.

*** Metadata
Each unit interacts with other game entities based on the metadata linked to
it. This metadata consists of keywords and numerical values, which determines
the units affiliation, and it's action's availability and
effectiveness. Different pars of a unit (eg ship/pilot/loadout/upgrade/talent)
contributes to differet meta values.

**** Unit Metadata

***** Faction

Faction is a ~keyword~ representing the faction which the unit belongs
to. Mission rules and card rules may refer to this keyword of a unit. Units with
the same faction keyword are ~friendly~ to eachother, unless stated otherwise by
a mission rule.

***** Affiliation

Affiliation is a logical group representing a player. It is marked by a color,
choosen by the player if mission rules don't specify it. Every unit with the
same affiliation is ~friendly~ to eachother.

***** Ship type

Ship type declares the chasses of the ship, it's default values, loadout and
upgrade slots.
Each ship type has the following numeric values associated:
- maximum hull value
- maximum shields value
- attack value
- movement points
- maneuverability points
Each ship type also lists two types of upgrade slots: ~system-upgrade~ and
~hardpoint~ slots. Additional weaponry might be attached to ~hardpoint slots~,
and system modifying upgrades can be installed to ~system-upgrade~ slots.

***** Hull

The ship's ~hull~ value represents it's physical condition. If this value
reaches 0, the unit dies. It's initial value is set by the ship's type.

***** Shields

The ship's ~shield~ value represents it's shields condition. Shields are a
defensive mechanism, lowering or neutralizing damage dealt to a unit. A unit
with shield value of 0 does not benefit from shield protection.

***** Attack value

The ship's attack value represents the firepower of it's primary
weaponry. During engagement the attack value of a ship is the number of dice
that the player may roll for a primary attack. Ships have a primary attack
value, set by their type, also different weaponrs might have different attack
values on one unit. More on this topic in [[*shooting][shooting.]]

***** Movement points

The ship's movement points are it's speed. Movement points are spend during
movement phase. For each point a unit may move one step. More on this in
[[maneuveurs]]. It's initial value is set by the ship's type.


***** Maneuverability points

The maneuverability points represent how many turns a unit may do in one maneuver
step. It's initial value is set by the ship's type.

***** Agility

The agility value represent how much can a ship turn after each step. This value
represents the amount of segments, and symmetrical to the velocity vector. It's
initial value is set by the ship's type.

***** Aim skill

This value represents the skill of the pilot in aiming. Affects how hard it is
for one blast to hit the target. It's initial value is set by the pilot.

***** Evasion skill

This value represents the skill of the pilot in evading incomming shots. While
defending, this value makes the unit harder to hit.

***** Actions list

This is a list of actions a unit may make. Actions can be given to a unit by a
ship (like targeting computer) or from the pilot (like focus), or a upgrade,
talent, or loadout.

**** Building a unit

Every metadata of a unit must be stored on a unit card or board, built by
the player from assets. Building a unit means the following:

1. Declare faction
2. Select one ship type from the factions ship list
3. Select an appropriate pilot from the factions pilot list
4. Select loadout for the ships loadout slots
5. Select talents for the pilots taalent slots
6. Select upgrades for the ships upgrade slots
